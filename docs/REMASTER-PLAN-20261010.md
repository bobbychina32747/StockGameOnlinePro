## 3. 目标架构与工程目录

保留 Web 产品形态。React 负责界面，图表采用现有 ECharts 能力；NestJS 负责 API 装配，游戏规则在不依赖 React、Nest 或 TypeORM 的纯 TypeScript 引擎内实现。这里的“引擎”指市场与游戏模拟核心，终端界面不引入与玩法无关的 3D 渲染依赖。

在项目内建立独立 `remaster/` 工作区，全部游戏核心重新实现。旧工作树作为兼容基线和回退参照，包含其未提交内容。待新版功能、数据和站点鉴权闭环后再讨论旧实现退役。

```text
remaster/
  packages/
    domain/         货币、账户、订单、持仓、市场规则、领域事件
    engine/         时钟、经济、参与者、撮合、风控、回放
    protocol/       REST/实时协议、错误码、版本与运行时校验
    design-system/  视觉变量、SVG 图标、控件与状态规范
  apps/
    game-api/       应用命令、身份适配、事务仓储、推送、健康检查
    web/            应用壳、市场会话、交易、资产、赛事、研究
  tests/            引擎性质、故障注入、API 与浏览器验收
  tooling/          本机启动、验证、迁移计划及对账工具
  docs/             规则、协议、功能覆盖、运行与回退说明
```

初始采用模块化单体与一个市场写者；不依靠启动多个 API 实例复制内存盘口。站点身份通过窄接口适配，游戏库拥有独立边界；不复制站点签名私钥，不把博客与云存档纳入游戏重写。

模块封装与显式导出符合 [NestJS 模块机制](https://docs.nestjs.com/modules)。资金修改只使用事务中的仓储与管理器，遵循 [TypeORM 事务约束](https://typeorm.io/docs/advanced-topics/transactions/)。客户端领域状态保持订阅和快照的一致性，参考 [React 外部状态订阅契约](https://react.dev/reference/react/useSyncExternalStore)。这些文档支持接口设计，不能代替项目实测。

## 4. 引擎与经济重建

### 市场时间与确定性

- `SimulationClock` 显式提供 marketId、sessionId、交易日、交易阶段、分钟序号和 simulatedAt。真实档与加速沙盒只改变时间推进方式，不改变规则。
- CN/HK/US 日长保留 240/330/390 分钟；午休不推进，US 跨午夜不切错交易日；CN 锁仓只在下一 CN 日解锁。沿用今天修复后的行为作为验收基线。
- 随机流分为宏观、行业、公司、参与者等，不直接使用 `Math.random` 或墙钟决定模拟结果。优先级使用单调命令序号。
- 版本化世界快照保存 RNG 状态、时钟、公司基本面、行业、新闻日历、AI 账户、盘口、待触发订单与结算进度。输入命令与事件可从快照重放。

### 价格、参与者与事件

- 经济引擎生成基本面、公平价值、宏观/行业冲击和交易意愿；价格发现、成交量和 OHLCV 按一个明确版本的成交/报价模型计算。
- 若展示合成的背景市场成交，须与实际参与者成交分开标识；同一真实 tradeId 的成交量只累计一次。
- 真人、AI、做市商使用同一订单与风控接口。做市商具备现金、库存与限额，不以无主挂单无限生成可兑现资产。
- 行业轮动、泡沫、黑天鹅与利好、IPO、财报预期差、分红、宏观数据有明确日历、持续期与因果链。玩家可见解释与 AI 信息权限区分，避免 AI 读取尚未公布的未来。
- 历史生成使用可复现 seed 与分段任务，避免启动时阻塞整个服务。日/周/月聚合由服务端权威数据生成。

### 撮合、账本与风控

- 所有现金、费用、冻结与债务采用货币最小单位整数；价格用整数 tick。边界值、溢出和货币精度显式检查。
- 市价、限价、止损、止损限价、FOK、IOC、冰山、自成交防护、部分成交、撤单、竞价、封板排队与盘后固定价交易都有确定的状态机。
- 撮合先生成待成交计划，再在单事务中保存双方账户、持仓、订单、复式账本、命令结果、可重放事件、世界版本、执行游标和 outbox；提交后按游标更新内存及广播。数据库提交后、内存应用前崩溃，必须从已提交记录恢复；内存应用失败立即停止接受写命令，完成恢复后才能继续。失败不得留下已吃掉的盘口或单边资产。
- 账本覆盖手续费、利息、初始资金、账户重置、分红与奖励；系统账户明确记录资金来源和去向。游戏允许的发行或回收必须是有原因的发行/回收记录，不能靠直接改余额隐式完成。
- `commandId` 按账户唯一，保存请求摘要：相同键相同请求返回原结果，相同键不同请求明确拒绝；网络超时以结果查询恢复，不直接再次成交。
- 持仓记录买入批次、可卖数量、融资负债及空头保证金归属。融资/做空/平空/强平使用同一计算规则。
- 换汇有独立报价、舍入、费用、双账户事务与账本。基金 NAV、收益分配和计息按游戏日幂等结算。
- 风控、比赛限制、账户重置资格与成就判定由服务端执行。

## 5. 后端、协议与站点接入

- 读模型与命令模型分离。新增有版本的游戏协议，保留站点会话、首次建号和旧号认领契约；迁移期间提供明确的旧客户端适配。
- 实时消息携带 protocolVersion、marketId、sessionId、sequence、simulatedAt、worldVersion。行情、盘口、事件、订单与资产可关联到同一已提交版本。
- 客户端发现乱序、重复、缺口或过期时，申请权威快照再继续增量；断线显示数据时间和只读状态。
- 订单预估由服务端提供费用、可买/可卖、冻结、市场规则与拒绝原因；成交前仍重新校验。
- 对外状态包括正在同步、实时、陈旧、休市、只读、故障。后台指标包括写者代次、队列、最后成功 tick、提交序号、对账差额和 outbox 积压。
- 站点令牌仍须验签及检查撤销、身份状态、角色与玩家映射。HTTP 和 Socket.IO 使用一致权限。第三方 OAuth client 令牌不自动取得交易账户权限。
- 交易库采用显式版本迁移，不开启生产自动 schema 同步。迁移脚本默认 dry-run，真实数据执行另行确认。

## 6. 美术与交互：交易所作战室

`art_director` 策略：

- 情绪关键词：紧张、克制、竞争。

- 禁用模式：表情符号充当主图标、所有模块同形圆角卡片、霓虹毛玻璃、装饰占据交易空间。

石墨底 `#101418`、分层面板 `#181E25`、纸白 `#E5E8ED`、琥珀 `#E5AF4B`。红绿仅用于行情语义，可按地区切换，并同时使用文字/箭头表达。中文使用系统字体，数字采用等宽与 tabular-nums。SVG 图标统一笔画，支持深浅主题、三语言与减少动画。

桌面：市场/自选导航 → 中央图表与公司资料 → 固定盘口/下单票据 → 底部持仓/订单台账；资产、赛事和研究独立可达。继续支持面板调宽与键盘导航。

移动：顶部可见市场切换；底部行情/资产/赛事/我的；详情提供图表与盘口，固定买卖入口开启下单抽屉。用户、市场、标的关联的草稿不因切 Tab 消失。提交中、结果未知、重试、拒单与部分成交具有明确反馈。

消息可关闭、去重，不重复弹出已取消的提醒。loading、empty、error、stale 区分显示。断网与账号切换清除跨身份数据，迟到响应不得覆盖另一个账户或市场。

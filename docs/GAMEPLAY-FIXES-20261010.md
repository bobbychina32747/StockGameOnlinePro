# 玩法修复与升级

本批次修复划转舍入造钱、单只平空释放全部保证金、杠杆费用导致负现金、三市场日长错误、跨市场 T+1 解锁、平仓后无法重置及基金分钟复利问题。

## 行为

- 划转金额必须为完整的分，到账金额向下取整；正式数据库中两个账户在同一事务保存。
- 存量账户的合并空头保证金按各仓位开仓市值与折算率分配。平仓只释放对应权重；普通平仓、全部强平与追保共用计算。这是合并保证金的兼容分摊方式，不会重置冻结总额。
- 杠杆买入的现金需求为成交额除以杠杆，加全额手续费。
- CN/HK/US 分别为 240/330/390 分钟。真实档按实际 session 分钟生成行情，午休不推进、美股午夜不换游戏日；收盘后结算。快档按各市场完整分钟数回绕。
- 账户计息、快照与日终强平按各市场各自收盘执行。
- CN 买入记录 `boughtDay`，只有下一 CN 游戏日解锁；HK/US 日初不参与。盘中升级时，历史缺少买入日的当日锁仓保守保留到下一 CN 游戏日。
- 零数量持仓不阻止重置，真实持仓、基金、挂单及赛季限制仍生效。
- ETF 改名“模拟A股指数 ETF”，按模拟 A 股等权组合总回报结算，含分红并允许下跌；货币基金目标年化 2.5%，按 252 个游戏交易日折算。两者不再按现实分钟增值。
- 存量基金 NAV 原值保留，不追回历史收益、不修改玩家基金份额或现金。基金报价写入失败时保留已持久化报价；同一结算日可重试。
- tick 携带服务端 K 线时间，前端优先使用；美股分时和回放按交易日合并午夜前后数据。

## 数据库升级

新增三个可空列：`positions.boughtDay INTEGER`、`fund_navs.settledDay INTEGER`、`fund_navs.basketPrices TEXT`。没有删除或重命名已有列。SQLite 升级脚本位于 `backend/scripts/migrate-gameplay-schema.cjs`，只添加缺失列，整个变更放在事务中；主程序执行前自动备份，并拒绝覆盖已存在的备份。

生产库关闭 `DB_SYNCHRONIZE` 时，必须先完成列升级再切换后端。建议在经核验的数据库副本上执行下面的命令，验收后再安排发布窗口：

```powershell
node scripts/migrate-gameplay-schema.cjs --db <数据库副本绝对路径>
```

本任务只在内存 SQLite 测试升级与事务回滚，没有执行玩家数据库迁移，也没有重启、发布或改动系统配置。回退到本次改动前代码时，可保留新增可空列；应使用同一份验收备份处理数据回退，避免混用已经发生交易的数据库版本。

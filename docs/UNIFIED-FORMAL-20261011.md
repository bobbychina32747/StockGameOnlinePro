# 统一正式版 2.0

## 资产策略

按玩家确认的方案，旧正式版 SQLite 是唯一正式资产账本。保留原用户/账户 UUID、现金、持仓、融资债务、空头保证金、基金份额、挂单、成交、成就和赛季记录。没有把余额复制到新世界，也没有追加 2.0 测试本金。基金持仓的小数份额仍以原账本数值保存；界面金额转换为整数分。

原基金份额和净值按人民币计价，港币/美元账户的基金市值、总资产和显示净值使用原后端当前汇率折算。转换只用于展示，不改基金份额、投入本金或账本余额。

2.0 测试 SQLite 在服务器单独一致性备份，停止测试引擎，原卷保留。测试资产不参与正式版交易与排名，不上传 Git。`/remaster/` 转到统一入口 `/`。

## 架构

`backend/` 负责原 SQLite、身份、唯一正式市场与撮合。`remaster/apps/game-api/unified-main.ts` 提供固定角色的 v2 HTTP/WebSocket 适配，`remaster/apps/web/` 提供统一工作台。独立回测/测试引擎仍在 `remaster/packages/engine`，正式服务不启动测试世界。

原后端 JWT 只在服务端；客户端持有不透明角色会话。站点续期和暂时超时不等于退出登录。v2 适配只读取当前角色资产，通过原受保护接口写交易，不直接改账本。

命令结果写入单独 `formal-commands.sqlite`，按角色和幂等键去重。提交后连接中断时，未确定结果的操作不自动重新扣款；需核对原账户记录，必要时由管理员在审计后处理未决记录。前端不能通过换键覆写旧幂等结果。

原始校准数据和研究方法见 [真实性报告](MARKET-REALISM-20261010.md)。`backend/src/common/unified-catalog.json` 和 `unified-intraday.json` 是 `remaster/packages/domain` 对应文件的构建输入副本；修改参数时必须同时更新，测试核对两份目录一致。

## 验证与回退

测试覆盖原 UUID、现金、债务、空头保证金、基金小数份额、T+1、300 条历史窗口之外的全部挂单；禁止跨区、两种登录同一原账户、HTTP 与真实 Socket.IO、价格分/元转换及命令去重/未决写保护。

部署先留存旧镜像、旧静态页面及 nginx 配置；一致性备份两版 SQLite，然后构建新镜像并检查服务。只有正式 API 和旧账本健康后才切换入口。`deploy/unified-rollback-ui.sh` 可恢复旧工作台与原行情 Socket，继续使用已扩展股票池的兼容后端。上线后玩家可能买入新增代码，因此不能直接降级到不认识新增代码的旧后端。正常回退不恢复旧数据库快照，避免丢失上线后的成交；灾难恢复需单独判断并停止写入。

发布源码时仅排除运行目录 `backend/data/`、`remaster/data/`；`backend/src/common/data/trading-calendar.ts` 是交易日历源码，必须包含。测试存档通过完整 SQLite `integrity_check` 后才写入验证标记；重试发布不能因为备份文件存在而跳过完整性检查。

身份会话在服务重启后需要重新登录，账户和资产持久化保留。旧管理员接口继续保留；用户工作台统一为一个入口。

# Source review and local hardening

This review uses the checked-out source, build configuration and executable tests. The starting revision was `f68d767`. It records local verification; publishing this source revision does not migrate the live service or production database.

## What the service boundary now guarantees locally

The game owns its user/account mapping and financial ledger, not site credentials, sessions or signing keys. Its environment profile is `.env.game`. Production rejects site-only configuration names without logging their values, and the native SQLite preparation hook rejects tables outside the game boundary before ORM synchronization. A production game file must already exist. Site access is accepted only after authoritative current-token validation; missing configuration, rejected credentials and upstream failures do not create game accounts or issue starting assets. Creation and binding retain transactions, uniqueness, origin checks and password proof.

The independent site owns its site tables. Its production configuration refuses an absent database, an in-memory database or automatic schema synchronization. Separate explicit exporters create a site-only database and a game-only database from the same immutable snapshot. They preserve IDs, game assets, encryption material, 64-bit integers and indexes, validate integrity, refuse an existing output and never modify the source. A new game file never receives site rows or the free-page remnants of dropped site tables. The old combined volume remains offline for rollback instead of being mounted by the game. Exporters have been exercised only with synthetic data.

The full local integration experiment used two complete applications, separate processes/databases and an ephemeral issuer key. It exercised site sign-in, repeat mapping, authenticated game access, logout revocation, absence of site routes in the game and native game registration. The test servers were stopped afterward. This is distinct from public-browser acceptance or a production migration.

The refreshed full bootstrap also checked finite, bounded OHLCV for the last sixty returned 1-minute and 5-minute bars in each of CN/HK/US, with recent calendar dates. It does not establish browser rendering quality or realistic financial dynamics. A separate native SQLite test covers the Thanksgiving closure, the following US half day, and restart without history regeneration. Post-close quote invariants have a deterministic event regression.

## Remaining boundaries

- Existing production identity/session IDs, signing and encryption keys, content/attachment mounts, administrator paths and current game balances still need a coordinated, authorized cutover. No production data was exported or reset in this change.
- The extracted site package currently uses the existing local dependency installation through a gitignored junction. A separate clean Linux dependency/container build has not been verified.
- Global backend strict mode, remaining dependency findings and legacy settlement paths are not declared solved by the pure-core gate or a passing test suite.
- Calendar format validation does not verify the truth of an announcement. The confidence labels and missing CN 2027 coverage are explicit.
- Full empty-database seeding remains expensive. The local complete integration boot took about eight minutes while other checks were running; this is not a deployment capacity or steady-state performance benchmark. Older synthetic daily prehistory remains approximate, and existing archives were not repaired by the new warmup path.
- Removing site files from the current source does not rewrite Git history. No history rewrite is part of this change.
